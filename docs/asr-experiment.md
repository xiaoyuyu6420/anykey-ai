# 识别率实测报告（本地 ASR，非代理指标）

## 为什么做这个

此前所有改进都只能用**代理指标**衡量（频带占比、信噪比、采样率）——
这些**不能证明识别率真的提高了**，而且代理指标与真实识别率的关系是可以被
错误假设的（本次实验就推翻了一个）。

用本地 ASR（sherpa-onnx + 中文 Paraformer int8，78MB）在**已知文本**的语音上
数字错率，得到可对比的硬指标。

## 方法

1. 取模型自带测试音频（普通话 2 段，54 字），参考文本 = 干净音频的识别结果
2. 按实测的键盘麦特性**劣化**：
   - `-6dB 搁架 @2600Hz`（实测该麦说话段 2-8kHz 仅占 1.33%，正常语音 4~5%）
   - 加**低频为主的噪声**（实测底噪 38% 能量 <200Hz，3kHz 以上几乎无能量）
   - 信噪比 7dB / 12dB 两档（实测该麦约 7dB）
   - 整体电平 0dB / -14dB 两档（实测键盘麦送来的语音 RMS 仅 600~1300，
     标准录音约 2900，差 10~14dB）
3. 把劣化音频过一遍**项目真实的 MicPipeline**，再送 ASR
4. 统计字错率（CER），样本量 54 字 × 2 信噪比 × 6 噪声实现 = **648 字次/配置**

## 结果

| 配置 | 0dB 输入 | -14dB 输入 | 合计错字 | 判定 |
|---|---|---|---|---|
| raw 原始 | 88 | 88 | **176** | 基准 |
| hp 去低频 | 95 | **83** | 178 | ≈等效 |
| **speech 补偿** | 89 | 86 | **175** | ≈等效 |
| full 完整（DFN3+AGC） | 105 | 135 | **240** | **变差 36%** |
| full+补偿（原「定稿」） | 108 | 134 | **242** | **变差 38%** |
| full+补偿+谱减 | 92 | 105 | 197 | 变差 12% |

### 两个结论

**① 完整处理链（DFN3 神经降噪 + AGC + 门控）显著损害识别**——错误从 176
增到 240~242（+36%~+38%），且低电平输入下恶化到 +53%。它此前是默认配置。

推测原因：该麦输入信噪比仅约 7dB，DFN3 在此低信噪比下几乎不提升信噪比
（实测 +0.1dB、而底噪与人声被等量削减），却会削掉语音成分；重度 AGC 又把
残余噪声一起抬起来。

**② 辅音区补偿（speech 档）对识别率是中性的**（175 vs 176，在噪声范围内）。

这推翻了此前的假设——「2-8kHz 弱 5dB 导致识别差」在理论上成立，
但现代 ASR 对频响倾斜相当鲁棒，实测看不到收益。**代理指标好看不等于识别率变好。**

## 最终配置

`micMode='speech'`（去低频轰鸣 + 辅音区补偿，不做降噪/AGC）+ `denoiseEnabled=false`。

选 speech 而非 raw 的理由：识别率与 raw 统计等效，但频谱与正常人声一致
（200-1kHz 占 64.7% vs 参考 65%），听感更自然；且去掉了低频轰鸣。
**这些都不能当作"识别率更高"的证据**——只是不损害识别率的前提下更好听。

## 复现

```bash
node tools/asr-sweep.js          # 只扫搁架补偿量
node tools/asr-pipeline-test.js  # 逐档过真实管线测 CER（本报告数据）
```

模型获取（直连，走代理会卡）：`github.com/k2-fsa/sherpa-onnx/releases`
的 `asr-models` 标签，`sherpa-onnx-paraformer-zh-small-2024-03-09.tar.bz2`
（78MB，解压到 `tools/asr-model/`，已在 .gitignore 中）。

## 未覆盖的范围（诚实边界）

- **微信输入法的实际表现仍未经实测**——本报告用的是 Paraformer。
  不同引擎对频响/降噪的敏感度可能不同，尤其「完整链有害」这一条需要
  在微信输入法上复核。
- 测试语料仅 54 字（普通话 2 段），小差异（1~3 字）不可信；
  只有成比例的差异（如 full 的 +36%）才可下结论。
- 劣化是合成模型，未必完全等同于真实麦克风。
